From cleaner to inspector

Make the agent's primary loop move + capture + analyze. Cleaning becomes a secondary, opt-in capability — not the reflex.

2026-06-29 · repo-grounded · ce-ideate · related: 2026-06-29-agent-messy-scene-viewability.html

The gap (grounding — observed live this session)

Watched the agent on two prompts and it ignored both:

"Orbit around the scene slowly" → orbited 1°, then ran remove_needles + opacity_threshold (unasked) and claimed it cleaned the scene.
"What is in this scene" → ran remove_outliers (unasked) and answered with Gaussian counts instead of describing what's actually visible.

Two root causes: (1) backend/agent/system_prompt.py frames the agent's identity around the floater-cleanup flow ("CLEANING:", "the flagship floater loop"), and (2) the local Qwen2.5-VL-7B model has weak instruction-following and pattern-matches every prompt onto inspect→clean→answer. The agent has good navigation/vision tools — it just doesn't treat looking and describing as its job.

basis: backend/agent/system_prompt.py · backend/agent/loop.py · live agent trace 2026-06-29

Top ideas (survivors)

#1 Reframe the agent: "inspector first, editor on request"shift

Rewrite system_prompt.py so the agent's stated identity is navigate, look, describe — and editing is a separate capability with a hard rule: never edit the scene unless the user explicitly asks to clean / remove / fix. The current prompt makes cleaning the default mental model; this flips it.

Why strong Cheapest possible fix, directly targets the observed failure, and is the foundation every other idea sits on. One-file change.

builds on: backend/agent/system_prompt.py

#2 Intent routing + tool-gating (INSPECT vs EDIT)shift

Classify each prompt up front into INSPECT (move/capture/analyze) or EDIT (clean), and only expose the relevant tool subset to the model that turn. In INSPECT mode the cleanup tools aren't even offered, so a weak model literally cannot clean when you asked it to orbit. The structural fix prose alone can't guarantee.

Why strong Robust against weak instruction-following — it removes the option instead of asking the model to resist it. The real cure for "it cleaned when I said orbit."

builds on: dispatcher / build_tool_specs in system_prompt.py + loop.py

#3 Vision-first scene descriptionanalyze

For "what is in this scene," the default answer should be capture_frame → describe the visual content (objects, layout, colors, setting) using the VL model's eyes — not a dump of Gaussian counts. Reserve metrics for explicitly quantitative questions ("how many / how messy"). Make description a first-class answer mode.

Why strong Directly fixes the "answered with counts" failure; it's the "analyze" half of your ask, and it's what a person actually means by "what is in this scene."

builds on: capture_frame + the VL model; demote get_metrics from the default answer path

#4 Autonomous best-view searchmove

Give the agent a real "find the best angle" behavior: capture_orbit several candidate views, score each for legibility (foreground fill, low empty/sky, subject centered), then settle the camera on the winner and narrate why. (Carried from the prior ideation — still the headline move capability the agent lacks.)

Why strong The marquee "move" behavior; now unblocked since this session fixed orbit actually orbiting. Buildable on existing tools.

builds on: capture_orbit, set_view, the orbit-arc fix landed this session

#5 Guided inspection tourmove

A canned "fly around and show me the scene" behavior: orbit + scan_pause at a few stops + narrate each + drop_marker on notable features. Turns "inspect" into a legible, demo-friendly sweep that ends in a spoken summary — the move+capture+analyze loop made concrete.

Why strong This is the new primary loop in one behavior, and it's exactly the "robot inspector" demo the project's north star calls for.

builds on: orbit, scan_pause, narrate, drop_marker, capture_frame

#6 Cleaning becomes opt-in / proposed, not reflexiveshift

Flip the bias: instead of cleaning unprompted, the agent describes the scene and offers — "this scene is ~39% floaters; want me to clean it?" — and only edits on a yes. Cleaning stays a first-class capability, just no longer the default action.

Why strong The clean expression of "cleaning secondary." Pairs with #1/#2 and makes the agent feel like a collaborator, not a bulldozer.

builds on: get_metrics + narrate + the EDIT-mode gate from #2

Considered & cut

  • Auto-capture + describe on every arrival — good perception habit, but it's a sub-mechanism of the inspection loop (#4/#5), not a standalone idea. Fold in.
  • Multi-view "contact sheet" UI — nice presentation surface; it's how #4 could display candidates, not a separate direction. Defer.
  • "Go look at the X" semantic navigation — bumps Tier-5 semantic selection, which ARCHITECTURE explicitly defers/refuses. Risky now.
  • Decouple the verify→revert loop from inspection — real, but it's the implementation of #2 (only EDIT mode carries edit-verify scaffolding), not its own idea. Merge.

How they map to your ask

Move → #4 (best-view), #5 (guided tour).
Capture → the mechanism inside #4/#5 (and feeds #3).
Analyze → #3 (vision-first description).
Cleaning becomes secondary → #1 (reframe identity), #2 (gate tools by intent), #6 (offer, don't reflex).

Recommended first brainstorm: #1 + #2 together — reframe the identity (cheap) and gate the tools by intent (robust against the weak 7B model). That's the literal "switch from cleaning to inspecting," and it makes #3–#6 stick. #3 is the close second (it fixes the "what is in this scene" failure outright).
